# Technical Specification: TodoMVC Full-Stack Application (MVP)

> Product requirements are defined in [mvp-prd.md](../prds/mvp-prd.md).

## 1. Architecture Overview & Tech Stack
- **Client-Server Architecture:** A unified full-stack Next.js application using the App Router for both the single-page frontend UI and stateless HTTP JSON Route Handlers (`/api/todos`).
- **Authentication:** None. All endpoints and static assets are publicly accessible without authentication headers, cookies, or tokens.
- **Synchronization Model:** Standard HTTP request/response persistence (no WebSockets required for MVP).

### 1.1 Tech Stack
- **Framework:** Latest LTS **Next.js** (App Router for frontend pages and backend API Route Handlers).
- **Language & Compiler:** **TypeScript 7** (`typescript@^7.x`, the native Go-based `tsc` compiler).
- **UI Component Library:** **shadcn/ui** (with Base UI primitives and Tailwind CSS).

### 1.2 TypeScript 7 & Next.js Side-by-Side Compatibility Setup
TypeScript 7.0 is the native (Go) port of the TypeScript compiler (`tsc`). Because TS 7.0 does not ship the legacy JavaScript programmatic `ts.*` API (`import ts from "typescript"`) required by Next.js's built-in build/editor plugins and `typescript-eslint`, this project **must use the official TS 6 / TS 7 side-by-side compatibility setup**:

1. **`package.json` Dependency Layout:**
   Install TypeScript 7 under `@typescript/native` (which provides the default `tsc` binary) and alias `typescript` to `@typescript/typescript6` (which provides the TypeScript 6.0 programmatic API and a separate `tsc6` binary so it does not collide with TS 7's `tsc`):
   ```json
   {
     "devDependencies": {
       "@typescript/native": "npm:typescript@^7.0.2",
       "typescript": "npm:@typescript/typescript6@^6.0.2"
     }
   }
   ```
   - Running `pnpm tsc --noEmit` executes the native **TypeScript 7.0** compiler.
   - Any tool importing `"typescript"` programmatically (Next.js `next build`, `next/typescript`, `typescript-eslint`) resolves to the compatible **TypeScript 6.0** API surface.
2. **`tsconfig.json` Configuration for TS 6/7:**
   - **No `baseUrl`:** `baseUrl` is removed in TS 7 (`ignoreDeprecations` is unsupported). Configure Next.js and `shadcn/ui` path aliases using relative targets in `compilerOptions.paths` (e.g., `"@/*": ["./src/*"]`) without `baseUrl`.
   - **Module & Resolution:** Use `"module": "esnext"` and `"moduleResolution": "bundler"`.
   - **Explicit `types`:** Because `types` defaults to `[]` in TS 6/7 rather than `["*"]`, explicitly declare `"types": ["node", "react", "react-dom"]` in `tsconfig.json` when ambient types are needed.

## 2. Data Model (`Todo`)

| Field       | Type                  | Constraints / Defaults                            | Description                                       |
| ----------- | --------------------- | ------------------------------------------------- | ------------------------------------------------- |
| `id`        | `string` or `integer` | Primary key, generated by backend                 | Unique identifier for each todo item              |
| `title`     | `string`              | Required, trimmed, non-empty (`length >= 1`)      | Task description                                  |
| `completed` | `boolean`             | Required, defaults to `false`                     | Completion status                                 |
| `createdAt` | `string` (ISO 8601)   | Required, generated on creation                   | Timestamp used for deterministic creation order   |

## 3. Backend API Specification

All request and response bodies use `Content-Type: application/json`.

### 3.1 Endpoints

1. **List Todos**
   - **Route:** `GET /api/todos`
   - **Response (`200 OK`):** Array of `Todo` objects ordered ascending by `createdAt` (or insertion order).

2. **Create Todo**
   - **Route:** `POST /api/todos`
   - **Request Body:** `{ "title": "Buy milk" }`
   - **Behavior:** Trims `title`; initializes `completed: false` and `createdAt`.
   - **Response (`201 Created`):** The created `Todo` object.
   - **Error (`400 Bad Request`):** Returned if `title` is missing, not a string, or empty after trimming.

3. **Update Todo**
   - **Route:** `PATCH /api/todos/:id` (or `PUT /api/todos/:id`)
   - **Request Body:** Partial update `{ "title"?: string, "completed"?: boolean }`
   - **Behavior:** If `title` is provided, trims it and validates it is non-empty. Updates the specified fields.
   - **Response (`200 OK`):** The updated `Todo` object.
   - **Errors:**
     - `400 Bad Request` if `title` is empty/whitespace-only or field types are invalid.
     - `404 Not Found` if `:id` does not exist.

4. **Delete Todo**
   - **Route:** `DELETE /api/todos/:id`
   - **Response (`204 No Content` or `200 OK`):** Confirms deletion.
   - **Error (`404 Not Found`):** Returned if `:id` does not exist.

5. **Bulk Toggle Todos (Toggle All)**
   - **Route:** `POST /api/todos/toggle-all` (or `PATCH /api/todos`)
   - **Request Body:** `{ "completed": boolean }`
   - **Behavior:** Sets `completed` to the target boolean value across all stored todos.
   - **Response (`200 OK`):** Updated list of `Todo` objects (or summary status).

6. **Clear Completed Todos**
   - **Route:** `DELETE /api/todos?completed=true` (or `DELETE /api/todos/completed`)
   - **Behavior:** Deletes all todos where `completed === true`.
   - **Response (`204 No Content` or `200 OK`):** Confirms bulk deletion.

## 4. Storage & Persistence Requirements
- **Durable Storage:** Todos must be stored in a persistent backend store (e.g., SQLite, PostgreSQL, or a durable file-backed database) so data survives server restarts and browser refreshes.
- **Validation & Integrity:**
  - Reject empty or whitespace-only `title` strings with HTTP `400 Bad Request`.
  - Return HTTP `404 Not Found` when operating on non-existent todo IDs.

---

## 5. Frontend Technical Specification
- **Routing & Filter State:**
  - Hash-based or history routing supporting `#/` (All), `#/active` (Active: `completed === false`), and `#/completed` (Completed: `completed === true`).
  - Route state must persist across page reloads and highlight the corresponding filter link.
- **DOM & Keyboard Behavior:**
  - Semantic HTML structure following TodoMVC conventions.
  - Autofocus on the new-todo input on initial load.
  - Inline edit input autofocuses on double-click, commits on `Enter` or `blur` (triggering `PATCH` if non-empty or `DELETE` if empty after trim), and cancels on `Escape` without firing a network request.
- **State Reconciliation & Error Handling:**
  - UI state must stay synchronized with backend API responses and handle failed network requests gracefully without corrupting client state.
